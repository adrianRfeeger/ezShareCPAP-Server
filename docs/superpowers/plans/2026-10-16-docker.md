# Docker deployment implementation plan

Goal: Package scheduled headless downloads and a read-only SMB snapshot share for a dedicated Proxmox LXC.

Spec: docs/docker-proxmox-plan.md. User requested creation on 16 October 2026 and chose an isolated worktree.

Execution: Inline implementation with regression tests and a final independent review. No server changes until the exact LXC and Wi-Fi assignment are verified.

Constraints: Preserve desktop behavior; Docker must not control Wi-Fi; failures must preserve published snapshots; credentials stay outside Git; local OSCAR profiles remain local.

- [x] Add existing-network mode to ezshare.py and cli.py. Test download without Wi-Fi calls and preserve managed-mode tests.
- [x] Harden file_ops.py. Test missing length, truncation, invalid listings, unsafe names, cycles and failure reporting.
- [x] Add server.py: strict config, shared flock, child-process timeout, snapshots, persistent status and daily timezone-aware scheduling. Test failure preservation, overlap, publication, restart and DST behavior.
- [x] Add approved authenticated web controls with CSRF protection, manual sync, schedule editing and 20-run history; verify in a browser.
- [x] Package Docker/Compose and Samba with secret-based authentication. Document installation, storage ownership, Wi-Fi prerequisites, manual operation and restore.
- [x] Run all tests, validate packaging where tools exist, and review. Report Docker and real-card/OSCAR checks separately.

Review focus: failed runs falsely succeeding; concurrent writers; card changes during transfer; snapshot consistency; SMB permissions; DST/restart duplicates; writable or untrusted remote paths.

Ruling: Use a small standard-library daily calendar scheduler rather than a cron dependency. This service needs one daily local time, persistent deduplication, explicit DST rules and no arbitrary jobs.


Validation: 57 tests passed, including a real local HTTP card served to the actual downloader child process. Compose YAML parsed; Samba entrypoint shell syntax passed. Browser validation confirmed authentication, dashboard rendering, and schedule persistence. Independent review findings were fixed, including secret-file ownership in the guide. Docker runtime, Wi-Fi, SMB and actual OSCAR import remain deployment gates because Docker is absent locally.

Server state: No Proxmox resources created or changed. The available Wi-Fi assignment method and target LXC configuration still require inspection before provisioning. The source checkout remains unchanged apart from the earlier planning document.
